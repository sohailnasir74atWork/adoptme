renders. Do not "fix" the upload content-type without re-testing the read.

## 2. GG potion values

### 2.1 The bug

The GG feed carried the **both-potions headline value in all four potion
states** for nearly every pet. Aestus published `0.03` for no-potion, ride,
fly and fly&ride, where amvgg.com shows `0.023 / 0.026 / 0.027 / 0.03`.

`GG/extractor.js` did this:

```js
out[`${field} - nopotion`] = num(np) ?? b;   // b = the headline
```

with the comment *"a blank cell means amvgg did not break that state out."*
**That assumption was wrong.** A null means *compute it*: amvgg publishes one
number per tier and derives the other three in the browser, multiplying the
headline by a coefficient picked on the pet's numeric `category`. 752 of 781
pets take that path.

Scope, measured before the fix and reproduced exactly by the diff after it:

| field | wrong |
|---|---|
| `rvalue - nopotion` / `- ride` / `- fly` | 758 / 781 each |
| `nvalue -` variants | 745 / 745 / 744 |
| `mvalue -` variants | 712 / 683 / 683 |
| **total** | **6,586 of 7,029 — 93.7%**, touching **758 of 781 pets** |

The base values were never wrong: all 2,343 regular/neon/mega values matched
amvgg exactly, with no missing or extra pets. The app was also never at fault —
`formatValue(0.023)` correctly returns `"0.023"`, and GG is already base-only
(`convert()` returns GG untouched; picking GG forces unit to Shark, a no-op).

### 2.2 amvgg's actual formula

Lifted from `/_next/static/chunks/app/values/pets/page-<hash>.js`. Branch order
matters — `GG/extractor.js → deriveVariants()` mirrors it:

| condition | behaviour |
|---|---|
| no coefficient row for the category | amvgg publishes the states explicitly — read them off the record. Only category 13 today. |
| `category === 11 && headline > 0.08` | flat `0.95` / `0.975` overrides the table; neon and mega stop scaling past `0.2` / `0.9`. |
| otherwise | `headline × coefficient` |

Rounding: the regular tier tightens to 3 decimals once the headline reaches
`0.0175`; neon and mega always keep 4. amvgg uses `Number(x.toFixed(d))` —
match it or the last digit drifts.

⚠️ **Two traps that cost real time:**

1. amvgg **ignores explicit values whenever a coefficient row exists.** Six
   pets (categories 5, 6, 11, 33, 99) carry both, and the *computed* figure is
   what the site renders. Preferring the explicit value there puts you back out
   of step with the site.
2. Category 13 is the *only* category absent from the coefficient table, and
   its explicit values legitimately sit **above** the headline — Bat Dragon is
   `5.175` no-potion vs `5.125` both-potions. That is not a bug.

### 2.3 Files changed (⚠️ that repo is NOT under git)

Originals preserved at `backups/2026-09-20-pre-potion-fix/`.

| file | change |
|---|---|
| `GG/scrape.js` | fetches the coefficient table each run, discovering the chunk from the pets page's own `<script>` tags. Writes `raw.json → coefficients`. **Throws** if not found. |
| `GG/extractor.js` | new `deriveVariants()`; refuses to run on a `raw.json` with no coefficients. |
| `GG/verify.js` | new regression check — see §2.5. |

The chunk hash changes on every amvgg deploy, so it **cannot be pinned**. The
throw is deliberate: falling back to the headline *is* the bug, and a silent
fallback would quietly reintroduce it.
