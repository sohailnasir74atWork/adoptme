## 3. Analytics: what was wrong and what changed

| Problem | Fix |
|---|---|
| The Hot badge read `score` (a rank, where 1 is best) as a value, so falling pets showed as "Hot +50%" | `valueChangeOf()` in `analyticsDataHelper.js` reads rvalue, then value, nvalue, mvalue, and ignores `score`. Diffs older than 7 days show no badges |
| "Demand" was mostly 30-day wishlists, and "Add" placeholder items topped it | Server now counts **7-day trade posts only** and excludes placeholders. `demandWindow: '7d'` marks the new data |
| Analytics screen doubled every count (`VM = 2`) | Removed |
| "How did trades go" wasn't trade results | Relabelled as the calculator's verdict when posting; only posts with both sides count; 7-day window |
| Busiest hour was in UTC; "Today" was a UTC day | Hours are shifted to the phone's time zone; the Today box is removed |
| Stale data looked current; the function swallowed errors | Warning when data is more than 48 h old; the function now rethrows on failure |
| Analytics disappeared when there were no movers | The Home Trending card always shows; lock icons removed |
| GG users got Elvebredd hot badges, and the GG chart showed a fake −99% cliff | Hot and drop maps are emptied in GG mode; the chart doesn't append the GG value and notes "History from Elvebredd values" |
| Share card called every two-sided trade "Fair" | Uses the calculator's verdict |

The liquidity thresholds are `liquidityFor()` in `analyticsDataHelper.js`, calibrated on the week of 2026-09-29:
- **fast:** 40 or more wants a week; or 20+ wants with wants ≥ half of offers; or 5+ wants that beat offers 1.5×
- **slow:** 8+ offers and offered at least 4× as often as wanted

## 4. Security lockdown: what the rules do now

**RTDB** (tested in the emulator, 91 cases):
- Admin, console and pipeline paths are `false`, including `factor`, `analytics`, `news`, `image_url` and `api` (write only).
- Per-user paths can only be written by their owner. Journal, stats, saved trades and alerts can also only be read by their owner.
- The old `chat_*` rooms (builds ≤1.9.8) work only for what those builds actually do. Faked admin or moderator badges are rejected.
- Deliberately left open to any signed-in user, because old builds need them: `group_meta_data/$uid/$groupId`, `mod_votes_summary`, `users_server`, `ratings`, `averageRatings`.
- Signed-out writes are allowed only on `_serverTime` (server time only), `news_feedback` (create-only, validated) and `like_counter` (numbers only).

**Firestore** (tested in the emulator, 81 cases):
- Users can create only as themselves. Others can change only their own reaction, like or vote entry, or a counter.
- Moderation (deleting other people's content, verifying scammer reports, polls) requires staff: a founder email or a `staff/{uid}` doc.
- Bulk listing of `user_profiles` and unfiltered `reviews` is closed.
- Old games and World Cup collections keep permissive signed-in rules, because old builds still call them.

**Deploy rules:**
- Firestore: always `npx firebase deploy --only firestore:rules --project adoptme-7b50c`. A plain `firestore` deploy also pushes the index file and could delete indexes created in the console.
- RTDB: `npx firebase deploy --only database --project adoptme-7b50c`.

**Emulator testing:**
- Harnesses are in the session scratchpad: `rules/rtdb-test.mjs`, `rules/fs-test.cjs`, and the RTDB generator `rules/gen_rtdb.py`.
- The Firestore emulator needs Java 21 or newer: use `/opt/homebrew/opt/openjdk@23/bin/java`. The Zulu 17 JDK is too old.

**Trap found in testing:** in RTDB rules, `data.child('x').val() >= 1` on a missing child throws, and one error fails the whole `.write`. Always guard it with `.isNumber()` first.

`DataFetching/adoptme/push-factor.js` now writes `/factor` with a gcloud Bearer token. It had been writing without authentication.
